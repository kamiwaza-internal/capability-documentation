# 1.3.4 release corpus review candidate

[`catalog.json`](catalog.json) is a sanitized, release-scoped index of the capability and recipe definitions at the pinned kit source. The site build prepares it as a **review-candidate** Markdown, PDF and ZIP download, separately from `site/data/publication.json`. In this source snapshot, `publication.sitePublished: false` records that the corpus was not live when reviewed; it is not a live-status monitor for a later deployment. CI generation does not establish live site publication or release approval. The download does not change a published release snapshot, enable the typed-recipe publication gate or establish a release binding.

The released product pin is Core tag `v1.3.4` at commit `5f5f64656802eb497167f6eae6021093cfcdccf2`. The original scoped SDK proof producer and original Kaizen UAT producer are separately pinned in `catalog.json`; neither producer commit replaces the product build. The source kit merge is `3678acc067afbe6ea84811eb7fcab18afbb7ad13`. The approved-session helper merge pin is supporting tooling, not a new UI proof. Source changes after these pins require a new reconciliation.

The corpus contains **107 capability definitions: 88 included and 19 excluded**. Six distinct included capability IDs have native-scored prerelease credit from **four complete scoped SDK recipe proofs**. A single proof may credit two reviewed IDs, so proof and capability counts are different. The separate technical release replay reports **30 of 88 scoped stamps, six failed selections and 52 unstamped**. These stamps do not convert the six prerelease credits into release approval. The source snapshot had **zero new complete UI recipe proofs**.

The 32 recipe definitions comprise 25 workbook and seven scoped programmatic definitions. They are a planning catalog, not 32 completed 1.3.4 journeys. All 32 lack a pinned complete UI observation; 28 need a reviewed 1.3.4 adaptation, 27 lack reviewed `verifies` claims, and one still needs a typed definition. The four established SDK proofs are marked separately. There is no authoritative versioned recipe-release listing, so every recipe's release membership is marked `unestablished` rather than inferred from its definition or source version.

The public file contains allowlisted IDs, titles, dispositions, source-declaration status, native prerelease status, recipe metadata, reviewed capability links, aggregate counts, and source/build commit pins. It contains no original receipts, raw tests, prompts, environment names, people, private source paths or URLs, proof-file hashes, credentials, or customer data. The private kit retains the original evidence and evaluator outputs. A future approved release publication still needs its own reviewed binding and privacy review; this review-candidate download is not that approval.
